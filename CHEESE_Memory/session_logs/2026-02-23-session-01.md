# Session Log: 2026-02-23 (Session 01)

## Summary
Successfully constructed and deployed the Proof-of-Concept inference pipeline for the Mamba-to-LoRA Hypernetwork. We scaffolded the PyTorch classes (`MambaStateCompressor`, `LoRAHypernetwork`, `DynamicLoRALinear`) and wrapped them in a completely decoupled FastAPI microservice (`server.py`). Fixed a critical OOM bug in the compressor by using Mean Pooling. Deployed the microservice to Opa-PC (192.168.2.194) and successfully initialized it on the GPU (CUDA) through WSL. Bridged the local `agent_wrapper.py` directly to the Opa-PC GPU using SSH Local Port Forwarding over port `8001`.

## Key Decisions
- Resolved out-of-memory errors by doing mean pooling across the sequence dimension before flattening the Mamba state.
- Bypassed convoluted WSL network bridging by creating a secure SSH tunnel mapping local port 8001 to Opa-PC port 8001.
- Changed default SSH shell on Opa-PC back to Windows CMD so `scp` works properly without `wsl.exe` crashing.

## Learnings
- [S] OpenSSH on Windows behaves terribly when `wsl.exe` is the default shell because `scp` tries to pass `-c` to the shell. Keep DefaultShell as CMD/PowerShell and prefix wsl commands.
- [S] Bypassing Windows/WSL vEthernet firewalls is significantly easier by just tunneling through SSH (`ssh -L 8001:127.0.0.1:8001`).
- [U] Laura appreciates fixing things locally (like Python scripts) before executing them blindly on remote servers.
