# Session Log: 2026-03-16 (Session 03)

## Summary
This session added a first simplification-gate prototype to the Phase 2 trainer: `activation_bias`, selectable via `--bridge-mode` while keeping dynamic LoRA as the default. The new mode injects additive per-target-layer bias vectors, reuses the existing target-layer/eval/checkpoint plumbing, and was verified remotely on Opa with dry-run plus checkpoint resume.

## Context Loaded
- `CHEESE_Memory/00_HANDOFF.md`
- `CHEESE_Memory/00_DASHBOARD.md`

- `MoCoP/experiments/mamba_lora_bridge/train_bridge.py`
- `MoCoP/experiments/mamba_lora_bridge/RUNBOOK.md`

## Key Decisions
- Keep LoRA as the default bridge mode and add `activation_bias` as an explicit alternative behind a flag.
- Reuse the existing patched linear wrapper instead of building a separate model patch stack, so `model.generate()` and target-layer routing stay unchanged.
- Ignore `--max-lora-delta-norm` in bias mode for now and only mirror the norm logging/control flow, not FiLM or extra clamp semantics.

## What Was Built / Changed
- Added `ActivationBiasHypernetwork` and bias-capable projection wrappers in `models.py`.
- Added `--bridge-mode` dispatch in `train_bridge.py` across runtime construction, random control generation, norm logging, checkpoint save/load, and dry-run.
- Added one `activation_bias` example command to `RUNBOOK.md`.
- Synced the patched bridge files to Opa and ran remote verification there.

## Findings
- `--dry-run --bridge-mode lora` still runs cleanly on Opa.
- `--dry-run --bridge-mode activation_bias` now runs cleanly, logs `bias_mean` / `bridge_bias_norm`, and saves checkpoints.
- `activation_bias` resume works cleanly from a saved dry-run checkpoint on Opa, so the new mode is checkpoint-compatible.
- The first activation-bias bug was a real broadcast issue in the wrapper (`[batch, out]` bias vs `[batch, seq, out]` output); fixing it required unsqueezing the bias on the sequence axis.

## Risks / Watch Out For
- This is only a trainer-side prototype. CognitiveBridge/server runtime deployment still defaults to LoRA and does not consume `activation_bias`.
- Bias mode currently reports clamp fraction as `0.0` because no bias-specific clamp rule exists yet.
- No real non-dry-run training was run yet; the next unknown is whether activation bias actually preserves the early constructive PPL signal better than LoRA.

## Unfinished / Next Session
- Run a cheap real `activation_bias` experiment beyond dry-run, ideally tiny-overfit first and then a small held-out eval.
- Compare `activation_bias` against current LoRA on the same target layers before touching FiLM.
