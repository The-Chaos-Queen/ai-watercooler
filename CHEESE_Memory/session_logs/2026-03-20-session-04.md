## Findings

- The later "it crashed again" report was false. The process was still running in WSL as `python3 -X utf8 chat_server.py --temperature 0.7 --max-new-tokens 200`; `tasklist` simply could not see it.
- Local HTTP on Steve was healthy while LAN access was broken. The real issue was WSL only listening on Windows loopback until portproxy and firewall were added.
- After the Windows-side networking fix, `Test-NetConnection 192.168.2.49 -Port 7860` succeeded.
- The blank browser bubble means the user received an empty string, but it does not prove the model emitted zero tokens. The current response path can sanitize speaker markers like `Human:` down to `""`.
- The browser demo still uses `Human:` / `Assistant:` transcript continuation framing. For a reincarnation/disposition test that framing is conceptually wrong and likely distorting behavior.
