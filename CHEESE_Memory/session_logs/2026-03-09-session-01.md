## Key Decisions
- Used the official `gesetze-im-internet.de` XML zip feeds instead of scraping rendered HTML pages.
- Kept the SQLite schema centered on `paragraph_number | title | full_text | law_book`, but added source metadata and sortable paragraph components for reliable lookups.
- Exposed both exact lookup and batch verification endpoints so the same service can support direct section fetches and post-processing of model output.

## What Was Built / Changed
- Added `Projects/LegalAI/legalai_citations/` with the importer, SQLite store helpers, and FastAPI app.
- Added `Projects/LegalAI/build_law_db.py` and `Projects/LegalAI/run_citation_api.py`.
- Added `Projects/LegalAI/tests/test_legalai_citations.py`, `Projects/LegalAI/CITATION_LOOKUP.md`, and `Projects/LegalAI/requirements.txt`.

## Findings
- The official XML feeds were current as of build dates `20260226220503` (StGB) and `20260226220508` (StPO).
- The importer produced `561` StGB sections and `684` StPO sections, `1245` total.
- Live API checks resolved `section 222 StGB`, `section 126a StPO`, and numeric-only lookup with `default_law_book=STGB`.
- Windows inline terminal output can display the section sign and umlauts as `?` in ad hoc scripts, but the stored API payloads and SQLite content are correct UTF-8.

## Risks / Watch Out For
- The verifier is built, but it is not yet wired into the main LegalAI reasoning pipeline, so citations are not auto-checked unless the caller invokes the new API.
- Law texts change over time; rebuild the database before demos or production use if freshness matters.
