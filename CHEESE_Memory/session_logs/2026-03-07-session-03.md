## Findings
- Live smoke worked through the cleaned canonical path with `qwen3.5-9b-uncensored-hauhaucs-aggressive` before LMStudio later refused to reload the same model.
- LMStudio currently rejects `qwen3.5-9b-uncensored-hauhaucs-aggressive` and `qwen3.5-4b` on this machine with memory-guardrail errors, despite both appearing in `/v1/models`.
- `qwen3.5-0.8b` still loads and validates the end-to-end MUD path, but its action quality is weak and often collapses to empty commands that now normalize safely to `look`.
- The command parser already supports destination-name fuzzy matching, so ugly exit keys like `Void` are mostly a human-facing polish problem rather than an agent-blocking traversal bug.

## Risks / Watch Out For
- LMStudio guardrails are now the main operational blocker for larger local Qwen 3.5 models.
- Evennia on Windows/Python 3.14 still carries the old stale-PID fragility if the server dies uncleanly.
- `Project_MUD/experiments/mamba_lora_bridge/` was already in a deleted/staged state and was intentionally left alone.
- Thornwick's tracked scratchpad changed during smoke testing and may need manual pruning if Laura wants a cleaner in-world memory state.
