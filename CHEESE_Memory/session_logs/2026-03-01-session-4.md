## Key Decisions
- Keep `00_HANDOFF.md` as a mutable boot-time control page and use `CHEESE_Memory/session_logs/` as the append-only archive.
- Do not push raw handoff state into Qdrant by default; ingest curated session logs instead.
- Extend existing metadata rather than inventing a parallel taxonomy: preserve `source_type`/`book` and add `project`, `trust_level`, `retrieval_priority`, and `ingest_mode`.
- Parse frontmatter during ingestion so session-log metadata actually reaches Qdrant.

## What Was Built / Changed
- Added repo-root `AGENTS.md` so Codex now has an explicit boot sequence for CHEESE files.
- Updated `.agent/workflows/start.md` and `.agent/workflows/end.md` to match the new handoff/session model.
- Added `.agent/workflows/session_log_template.md` as the canonical session log shape.
- Reworked `CHEESE_Memory/00_HANDOFF.md` into a multi-agent control page with owner tracking, edit ledger, session-log linkage, and Qdrant sync state.
- Extended `Project_Prosthetic/ingest_sessions.py` to ingest `Research/` and `MoCoP/`, parse frontmatter, infer projects, and normalize metadata.
- Updated `Project_Prosthetic/memory_engine.py` and `Project_Prosthetic/recall.py` so retrieval now understands both legacy `type` payloads and current `source_type` metadata.

## Findings
- The ingest pipeline previously wrote `source_type`, but retrieval still filtered and displayed `type`; that mismatch would have silently degraded filtered recall.
- Session-log frontmatter was being ignored before this pass, so fields like `session`, `agent`, `tags`, and `qdrant_sync` never entered Qdrant.
- `00_HANDOFF.md` is intentionally excluded from bulk ingest, which is correct; the handoff should track memory sync state, not pretend to be durable memory.
